# Distribution via `databricks aitools` (agent skills)

Starboard ships its skills through two channels; both draw from the **single
canonical skills tree** at `packages/starboard-skills/skills/starboard/` (vendored
into `plugin/skills/` by `scripts/vendor_plugin_skills.py`).

1. **Claude Code / Isaac plugin** — the `plugin/` bundle + `marketplace.json`
   (see [HOST_COVERAGE.md](./HOST_COVERAGE.md)).
2. **`databricks aitools`** — the Databricks agent-skills channel, which auto-detects
   installed coding agents and deploys skills to their skill dirs (`~/.claude/skills/`, …).

## `databricks agent-skills` format (confirmed, G4)

Reference: <https://github.com/databricks/databricks-agent-skills>.

- **Layout:** each skill is a directory with `SKILL.md` + an optional `references/`
  folder (loaded on demand).
- **`SKILL.md` frontmatter:** `name` (identifier), `description` (purpose), and an
  optional `parent` (e.g. `parent: databricks-core`). Starboard skills additionally
  carry `allowed-tools` for the Claude Code channel — a superset that the agent-skills
  channel ignores, so one `SKILL.md` serves both.
- **Manifest:** `manifest.json` is **generated** from the skill dirs + frontmatter
  (`python3 scripts/skills.py`; validate with `scripts/skills.py validate`) — never
  hand-edited. The CLI reads it to discover skills.
- **Install:**

  ```bash
  databricks aitools install                      # auto-detect agents, deploy all
  databricks aitools install <skill> [--experimental]
  ```

## Bringing Starboard skills into the agent-skills channel

To publish through `databricks aitools`, mirror the canonical tree into the
agent-skills layout and (optionally) set `parent: databricks-core` in each
`SKILL.md`; the manifest is then generated by the channel's `skills.py`, not by hand.
The canonical tree remains the single source of truth — do not fork skill content per
channel.

> Naming: skill dirs follow `starboard-<domain>` (e.g. `starboard-warehouse`,
> `starboard-workload-review`), and `SKILL.md` `name` matches the directory. Keep the
> two channels consistent by regenerating both from the canonical tree.
